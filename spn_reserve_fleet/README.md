# Панель резервных IP WAY SPN

Панель управляет установками WAY SPN на уже купленных VPS и следит за
резервными IPv4, назначенными у хостера.

Панель показывает созданные серверы, текущие и резервные IP, ответ SSH,
число последовательных отказов и историю переключений. Можно добавить или
убрать резерв из панели, включить автосмену, проверить SSH и вручную выбрать
резервный адрес. Удаление резерва из панели не удаляет IP у хостера.

## Создание и перенос VPS

- **Добавить сервер.** Введите публичный IPv4 чистой Ubuntu 24.04, SSH-порт,
  пароль root, тип подключения, название и сквады. Домен в зоне
  `wayspn.com` можно указать или оставить на выбор панели. Сверьте
  отпечаток SSH с консолью хостера перед запуском. Пароль VPS не сохраняется.
- **Yandex CDN.** После подготовки VPS панель покажет домены и настройки.
  Создайте сертификат и ресурс в консоли Яндекса, внесите два CNAME
  в задачу и запустите финальную проверку. Подключение публикуется после
  проверки трафика. Для CDN доступен перенос VPS, мониторинг проверяет SSH
  источника.
- **Перенести на новую VPS.** Откройте это действие в карточке существующей
  управляемой установки и укажите новую VPS с прежним SSH-портом.
  Программа сохраняет домен, параметры подключения и сквады. При
  переключении может потребоваться переподключение клиента. Удаляйте старую
  VPS у хостера после сообщения об успешном переносе и проверки подключения.
  Добавьте резервные адреса, назначенные уже новой машине.

Прогресс виден в разделе «Установки и переносы». При ошибке продолжайте
существующую задачу с тем же IP. Если служебный ключ ещё не добавлен,
введите пароль VPS повторно.

## Откуда проверять

Для текущей установки выбрана московская VPS `129.101.97.242`
(`msk-1-vm-dtol`): пользователь сравнил проверки SSH с Mac без VPN и с этой
VPS, результаты для трёх тестовых адресов совпали. Панель работает по адресу
[ip.wayspn.com](https://ip.wayspn.com), служба запускается после перезагрузки.
Mac и телефоны не нужны для постоянной работы.

Результаты характеризуют сеть этой VPS. Если позже потребуется проверять
ограничения конкретного домашнего или мобильного оператора, нужна отдельная
точка в его сети. Проверки из зарубежного дата-центра могут показывать
заблокированный у вас адрес рабочим.

Телефон подходит для управления панелью. В этой версии проверки выполняются
машиной с программой, а не браузером телефона. Постоянный мониторинг на Android
потребовал бы отдельного приложения с постоянным уведомлением; обычный
периодический WorkManager допускает минимальный интервал 15 минут и задержки.
iOS не гарантирует точное расписание фонового выполнения. Для непрерывных
проверок по 30 секунд домашняя машина проще.

Источники по ограничениям телефонов:
[Android WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work),
[Apple BackgroundTasks](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app).
В этой версии одна точка проверки; приложение и согласование результатов
из двух городов не реализованы.

## Как работает автосмена

1. Каждые 30 секунд соединяется с текущим IPv4 на SSH-порту и ждёт настоящий
   баннер SSH, не более пяти секунд. Пароль для проверки не нужен.
2. После трёх последовательных отказов проверяет резервы по порядку добавления.
3. Если резерв отвечает, ещё раз проверяет текущий IP и запускает
   `ops/universal-reality/change_ip.py --ssh-only --non-interactive --apply`.
4. Скрипт проверяет закреплённый ключ SSH и идентичность прежней VPS,
   назначение адреса, исходящий маршрут и его сохранение после перезапуска.
   Атомарно переносит разрешение VPN-порта на новый IP и проверяет сохранение
   фильтра после загрузки. Затем обновляет A-запись DNS, проверяет DNS и адрес
   управления Remnawave. Ошибка защиты останавливает переключение до завершения
   журнала; неподтверждённая смена не считается успешной.
   Домен, сертификат TLS, UUID, профиль и клиентские настройки сохраняются.
5. Новый адрес становится текущим, старый остаётся в резерве. Между
   переключениями выдерживается пауза пять минут.

Проверка SSH достаточна для принятия решения. Проверка трафика VPN или
подписки при автосмене не выполняется; журнал явно отмечает этот режим.
С учётом трёх отказов, применения и TTL DNS восстановление занимает несколько
минут, а не происходит мгновенно. Клиент может потребовать переподключения.

Если все адреса недоступны, изменений нет. Это также предотвращает смену всех
IP при пропадании домашнего интернета. Если переключение прервано или ответ
потерян, программа сверяет журнал. Незавершённая операция останавливает
автосмену и требует продолжения с тем же IP; другой резерв вслепую не выбирается.

Панель показывает адрес незавершённой операции и кнопку «Продолжить» только
для него. Безопасная причина отказа и ID приватного журнала сохраняются после
сканирования: ошибка SSH, изменение привязок, DNS или маршрута не заменяются
общим сообщением. Сырые журналы и пути служебных файлов через API не выдаются.

Устаревшую установку после переустановки VPS можно перевести в архив.
Она исчезнет из основного списка и мониторинга, управление будет отключено;
история, резервы и незавершённые операции останутся в отдельном разделе.
Архив не определяется автоматически по совпадению IP. Команда выполняется
на контроллере с его приватным каталогом данных:

```sh
python3 -m spn_reserve_fleet --data-dir КАТАЛОГ_ПАНЕЛИ archive \
  --server СТАРЫЙ_ДОМЕН --reason "Установка заменена новой" --replacement НОВЫЙ_ДОМЕН
```

Команда `restore --server ДОМЕН` возвращает запись из архива, оставляя
автосмену выключенной. Сканирование само по себе архивные записи не возвращает.

Автосмена изначально выключена для каждого добавленного сервера. После
перезапуска сохраняются резерв, настройки и число отказов. Старая серия
отказов обнуляется после большого перерыва. Переключение одного сервера
не останавливает проверку остальных (до восьми параллельных задач).

## Запуск на этом Mac

Из каталога репозитория:

```sh
cd ~/Downloads/SPNvpnF
python3 -m spn_reserve_fleet init
python3 -m spn_reserve_fleet serve
```

`init` запросит собственный пароль панели минимум из 16 символов. Затем
откройте [панель](http://127.0.0.1:8787), добавьте резервные IP и включите
автосмену нужных серверов. `serve` запускает и панель, и монитор.
Компьютер должен оставаться включённым и не спать.

Зависимости панели уже есть в основном `requirements.txt`: `fastapi`,
`uvicorn`. Сам монитор и его хранилище используют стандартную библиотеку Python.
Для операций DNS нужен `dig`; для управления — OpenSSH и доступ по ключу
без ввода пароля. Скрипт развёртывания поддерживает Ubuntu 24.04 на VPN VPS.

При настроенном `~/.config/spn/reserve-controller.json` новые завершённые
установки `ops/universal-reality/deploy.py` автоматически передаются на VPS.
Во время существующего доверенного SSH-соединения установщик добавляет
публичный ключ контроллера к ноде; приватный ключ остаётся на контроллере.
Без этой настройки установки регистрируются локально в `~/.spn-reserve-fleet`.
Панель также периодически подхватывает
завершённые прямые установки с доменом из `~/.spn-reality-deploy` и учитывает
последнюю ручную смену IP. Незавершённые, IP-only и VK-релейные установки
автоматически не подключаются.

При смене IP той же VPS адрес подключения задаётся отдельно, в приватном
`~/.config/spn/reserve-controller-transport.json` с правами `0600`:

```json
{"format":1,"controllers":[{"host":"147.45.164.28","port":22,"connect_host":"129.101.97.242","bind_interface":"en0"}]}
```

Исходный `host` в `reserve-controller.json` и журналах остаётся идентификатором
контроллера; OpenSSH проверяет прежний доверенный ключ через `HostKeyAlias`.
`connect_host` задаёт новый адрес. Необязательный `bind_interface` выбирает
локальный сетевой интерфейс: здесь `en0` нужен для регистрации с Mac через
физическое подключение. Без него используется обычный системный маршрут.

Для установки с нестандартным каталогом:

```sh
python3 -m spn_reserve_fleet import --state-dir /ПОЛНЫЙ/ПУТЬ/К/ЖУРНАЛУ
```

Если выбран отдельный каталог панели, укажите его и при запуске программы,
и в установщике (`--fleet-dir`). Иначе скрипт зарегистрирует сервер в
каталоге по умолчанию, а нестандартную установку потребуется импортировать.

## Доступы для переключения

Проверка баннера SSH не требует пароля или ключа. **Смена IP требует**
доступа `root` по SSH-ключу, доступному процессу мониторинга без интерактивного
ввода. Закреплённый отпечаток VPS берётся из завершённой установки, в том
числе после прежней смены IP. Адрес чужой VPS не будет принят как резерв
этой установки.

В `.env` репозитория должны быть `REMNAWAVE_BASE_URL` и
`REMNAWAVE_API_TOKEN`. Можно использовать другой файл:

```sh
python3 -m spn_reserve_fleet --env-file /etc/spn/reserve.env serve
```

URL должен совпадать с панелью исходной установки. Для Cloudflare используется
`CLOUDFLARE_API_TOKEN` из окружения/`.env` или приватный файл
`~/.config/spn/cloudflare-token` с правами `0600`. Токены не нужно вводить в
веб-панель. Они не передаются на VPN VPS.

Перед включением автоматики проверьте **одну** ручную смену через панель.
Это подтвердит SSH-ключ, права API и совместимость сети VPS.

## Новые TLS-серверы и ручная смена

Новые установки теперь по умолчанию используют VLESS TCP TLS/Vision и
сертификат Let’s Encrypt на собственный домен:

```sh
python3 ~/Downloads/SPNvpnF/ops/universal-reality/deploy.py \
  --ip 217.60.30.79 \
  --domain de11-1-1.wayspn.com \
  --name "🇩🇪 Германия" \
  --country FI \
  --apply
```

На чистой VPS должен быть доступен TCP80 для выпуска и продления сертификата,
TCP443 — для VPN. Продление автоматическое; после него перезапускается
собственный контейнер ноды. Новые TLS-установки также показывают обычный сайт
при HTTPS-запросе без VPN-аутентификации; поддерживаются HTTP/1.1 и HTTP/2.
Прежние сохранённые Reality-установки продолжают
использовать Reality: повтор команды не мигрирует рабочий сервер на TLS.
Для новой установки Reality можно явно задать `--transport reality`.

## Защита резервных адресов и проверок извне

Новые установки автоматически получают отдельный сетевой фильтр. Входящий
TCP443 доступен только на текущем IPv4. На резервных IPv4 и на IPv6 этот VPN-порт
закрыт, даже если сам процесс слушает все адреса. При смене IP правило меняется
одной атомарной операцией до DNS; фильтр восстанавливается собственной службой
после загрузки. Таблицы UFW/Docker, маршруты и назначенные адреса не очищаются.

Порт SSH, обычно 22, остаётся доступным для проверок на всех назначенных IPv4.
Фильтр известных сканеров может блокировать их подключения и к SSH. Московский
контроллер `147.45.164.28` и IP панели исключены из фильтра сканеров; эти исключения
не открывают VPN-порт на резервных адресах.

Используется публичный список
[traffic-guard antiscanner](https://github.com/shadow-netlab/traffic-guard-lists/blob/main/public/antiscanner.list).
Это список сообщества, а не достоверный перечень всех проверяющих РКН.
Широкий список государственных сетей не подключается. Исходный снимок закреплён
по версии; ежедневный таймер загружает обновление по HTTPS, проверяет формат,
размер и ширину диапазонов и лишь затем применяет его. При ошибке загрузки или
проверки продолжает работать последняя подтверждённая политика.

Для REALITY дополнительно проверяется SNI: HAProxy пропускает только настроенное
имя целевого сайта. Постороннее или отсутствующее имя отклоняется до ядра Xray;
правильное имя сохраняет прежний REALITY и его сайт маскировки. Это отдельное
обновление с собственным журналом, исходные ключи, профиль и UUID не меняются.

Уже зарегистрированные серверы обновляются **на центральной VPS**. Подставьте
домен сервера из панели; глобальные параметры стоят перед `harden`:

```sh
ssh root@129.101.97.242
cd /opt/spn-reserve-fleet/current
runuser -u spn-reserve -- \
  /opt/spn-reserve-fleet/venv/bin/python -m spn_reserve_fleet \
  --data-dir /var/lib/spn-reserve-fleet/.spn-reserve-fleet \
  --env-file /var/lib/spn-reserve-fleet/config/remnawave.env \
  harden --server ДОМЕН_СЕРВЕРА --apply
```

Без `--apply` выводится план. Команда проверяет ключ SSH и прежнюю VPS, при
необходимости подключается через доступный резерв для управления, но текущий
IP не меняет. Для старого TLS добавляет сайт и совместимые fallback-настройки
собственного профиля; для REALITY добавляет фильтр SNI. Транспорт не мигрирует.
Если есть незавершённая смена IP, сначала нужно продолжить её на тот же адрес.
Прерванный `harden` повторяют для того же сервера; исходный план не переписывается.

Эти меры уменьшают доступную сканерам поверхность. Они не гарантируют защиту
от блокировки IP или диапазона и не устраняют пассивный анализ трафика у
провайдера/ТСПУ. Обычный HTTPS-сайт и сертификат также не доказывают, что весь
VPN-трафик неотличим от браузера.

Ручная смена на заранее назначенный IPv4 той же VPS, с проверкой по SSH:

```sh
python3 ~/Downloads/SPNvpnF/ops/universal-reality/change_ip.py \
  --domain de11-1-1.wayspn.com \
  --ip НОВЫЙ_IP \
  --ssh-only \
  --apply
```

Без `--apply` — только план. Без `--ssh-only` сохраняется подробная проверка
VPN-трафика и выгрузки подписки, которой нужен локальный тестовый Xray.
Сама смена IP не переустанавливает VPN или сеть. Для замены самой VPS
используйте действие «Перенести на новую VPS» в карточке.

Прерванную автоматическую операцию продолжайте через кнопку «Назначить»
того же резервного адреса или той же командой с прежними `--state-dir`,
`--ssh-only --non-interactive`. Режим незавершённой операции менять нельзя.
После исправления ошибки автосмену нужно включить снова. Подробные логи
подпроцесса находятся в `~/.spn-reserve-fleet/logs`, права `0600`.

## Постоянная машина с Linux

Скопируйте репозиторий, завершённые исходные журналы из
`~/.spn-reality-deploy` (каталоги `0700`, файлы `0600`), доступы API и
нужный SSH-ключ в учётную запись, запускающую монитор. Создайте окружение
Python 3.10+ с `fastapi` и `uvicorn`, установите `openssh-client` и `dnsutils`.
Запустите `init` от имени этой учётной записи. Если журналы переехали,
выполните `scan`/`import` на новой машине, чтобы пути в инвентаре были актуальны.
Не включайте одновременно автоматику для одной VPS на двух машинах.

Шаблон службы: [spn-reserve-fleet.service](deploy/spn-reserve-fleet.service).
В нём нужно подставить свои пользователя, каталог репозитория, Python и
файл `.env`. Шаблон запускает панель на `127.0.0.1:8787`.

Для доступа с телефона по интернету поставьте перед панелью HTTPS reverse proxy
на выбранной машине. Для доступа в домашней Wi-Fi сети можно явно выбрать
LAN-адрес через `serve --host IP_МАШИНЫ`. По умолчанию панель видна только
локально; публичный URL автоматически не публикуется.

### Выполненная установка на московской VPS

- URL: [https://ip.wayspn.com](https://ip.wayspn.com), nginx и сертификат
  Let’s Encrypt с автоматическим продлением.
- Служба: `spn-reserve-fleet.service`, пользователь `spn-reserve`.
- Код: `/opt/spn-reserve-fleet/current`, Python:
  `/opt/spn-reserve-fleet/venv/bin/python`.
- HOME: `/var/lib/spn-reserve-fleet`, состояние:
  `/var/lib/spn-reserve-fleet/.spn-reserve-fleet`.
- Только необходимые API-настройки:
  `/var/lib/spn-reserve-fleet/config/remnawave.env`, права `0600`.
- Пароль веб-панели сохранён отдельным приватным файлом на Mac:
  `.local-state/reserve-fleet/panel-login.txt`; в исходники он не включается.

Для подключения уже завершённой установки на Mac:

```sh
python3 -m spn_reserve_fleet handoff --state-dir /ПОЛНЫЙ/ПУТЬ/К/ЖУРНАЛУ
```

Перед передачей локальное управление блокируется. Повтор передачи безопасен:
новые центральные журналы и последующие смены IP не перезаписываются старой
копией с Mac. После передачи ручные смены выполняются через центральную
панель или CLI на VPS. Прежний локальный `change_ip.py --apply` откажется
управлять переданной установкой.

SSH-ключ Mac для регистрации ограничен на контроллере только командой
приёма журналов. Он не даёт обычного root-доступа и не передаётся VPN-нодам.
Публичный ключ **контроллера для управления нодами** находится на Mac в
`.local-state/reserve-fleet/node-management.pub`. Для ранее созданной ноды
его нужно один раз добавить, выполнив с Mac с рабочим доступом к ней:

```sh
ssh-copy-id -i /Users/khamzat/Downloads/SPNvpnF/.local-state/reserve-fleet/node-management.pub root@ТЕКУЩИЙ_IP_НОДЫ
```

Новые установки с настроенным контроллером добавляют этот публичный ключ
сами. Пароль или приватный SSH-ключ ноды контроллеру не требуется.
Для наблюдения за SSH добавлять ключ не нужно; он нужен для смены IP.

Для установки на другой VPS: `deploy/build_bundle.py` создаёт архив только
исходников, `deploy/install.py` устанавливает службу, `deploy/setup_https.py`
настраивает HTTPS выбранного домена. По умолчанию эти установщики показывают
план, применение требует `--apply`.

## Другие команды

```sh
python3 -m spn_reserve_fleet status
python3 -m spn_reserve_fleet scan
python3 -m spn_reserve_fleet reserve --server ДОМЕН --ip РЕЗЕРВНЫЙ_IP
python3 -m spn_reserve_fleet auto --server ДОМЕН --enabled yes
python3 -m spn_reserve_fleet check --server ДОМЕН
python3 -m spn_reserve_fleet switch --server ДОМЕН --ip РЕЗЕРВНЫЙ_IP --apply
python3 -m spn_reserve_fleet --env-file /ПУТЬ/К/panel.env harden --server ДОМЕН --apply
python3 -m spn_reserve_fleet monitor
python3 -m spn_reserve_fleet serve --no-monitor
python3 -m spn_reserve_fleet password
```

`check` может выполнить смену после достижения порога, если автосмена включена.
`status` ничего по сети не проверяет. `--no-monitor` нужен, если отдельный
процесс `monitor` уже запущен. Два монитора с одним каталогом не запускаются.
Параметры до подкоманды: `--interval 30 --failures 3 --cooldown 300`.

Проверки разработки не обращаются к реальным VPS:

```sh
python3 -m unittest discover -s tests -p 'test_reserve_fleet*.py'
python3 -m unittest discover -s ops/universal-reality -p 'test_*.py'
```
