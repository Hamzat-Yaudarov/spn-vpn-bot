# Восстановление выдачи после оплаты — 31.08.2026

Все команды ниже выполняются на **сервере бота `spnde`**, проект
`/root/spn-vpn-bot`. Панель, PostgreSQL панели и VPN-ноды не останавливать.

## Что подтверждено

В логе режим API уже 3. Поиск нового пользователя падает с
`User lookup endpoint unavailable` (HTTP 404 без ожидаемого кода A025).
Старый обработчик при каждой повторной проверке создавал новую пустую строку
подписки и не закреплял её за платежом до самого конца. Затем возникала ошибка
`Нет свободного внутреннего слота подписки`. Это сбой выдачи, а не требование
повторной оплаты. Тело исходного HTTP 404 прежний лог не сохранял, поэтому
конкретную причину ответа прокси/панели по нему установить нельзя.

Исправление нормализует URL API и при неоднозначном 404 сверяет точное имя
пользователя с валидным списком API. Неполный список, ошибка авторизации или
сети не считаются доказательством отсутствия пользователя.

Платёж закрепляется за одной подпиской и абсолютным сроком ДО обращения к
панели. Подписка и статус `paid` сохраняются одной транзакцией, после успешной
синхронизации срока и получения ссылки. Защита повторного выполнения есть
в процессе бота и в PostgreSQL. Лимит остаётся пять видимых подписок каждого
типа; номера внутренних строк больше не ограничивают хранение истории.

При восстановлении повторные пустые строки одного номера скрываются,
но не удаляются. Строки с ключом, сроком или связями с другой покупкой не
перепривязываются автоматически. Ожидающие платежи больше не удаляются по
возрасту ни фоновой очисткой, ни при запросе нового счёта.

## 1. Остановить бот и установить исправление

```bash
sudo systemctl stop spn-bot
```

Бот, сайт и MiniApp временно недоступны; уже открытые платёжные ссылки ещё
могут принимать оплату. Работающие VPN-ноды продолжают работать.

Если изменения уже опубликованы вами в GitHub, обновите проект обычным способом.
Сам по себе `git pull` не переносит неопубликованные изменения с Mac.

Альтернатива — подготовленный архив `way-spn-payment-hotfix.tar.gz`.
Передайте его с Mac на сервер **бота**, затем:

```bash
cd /root
tar -xzf /root/way-spn-payment-hotfix.tar.gz
python3 /root/way-spn-payment-hotfix/install_hotfix.py /root/spn-vpn-bot
```

Установщик проверяет старые/новые хеши всех файлов ДО замены. При сторонних
изменениях он останавливается, ничего не перезаписывая. Перед заменой сохраняет
копию файлов. `.env`, systemd и база данных установщиком не изменяются.

```bash
cd /root/spn-vpn-bot
./venv/bin/python -c 'import config; print("Режим API:", config.REMNAWAVE_API_VERSION)'
```

Нужен режим **3**. Если показано 2, в `.env` бота установить
`REMNAWAVE_API_VERSION=3`, без повторяющихся строк. Не менять API-токен, ключи
клиентов, ID или статусы оплат вручную.

## 2. Проверить зависшие покупки — без изменений

```bash
./venv/bin/python scripts/recover_paid_subscriptions.py --since 2026-08-30
```

Скрипт читает ожидающие оплаты подписок и сверяет через API платёжного сервиса
статус, ID, сумму в RUB, владельца и тариф. Не создаёт платежей, не списывает
деньги, не выдаёт подписок и не отправляет сообщения в режиме проверки.

Ожидаемый вывод по успешной оплате: `ОПЛАЧЕНО ... подписка=...`.
Если указана ручная сверка — сначала разобраться с этой строкой. Старые
продления без сохранённого срока активации автоматически не повторяются:
прежний код мог уже добавить дни до ошибки. Аналогично не перепривязываются
уже выданные ключи к новой покупке с занятым номером.

Проверяются только существующие записи в `payments`, только покупки подписок,
не ГБ/устройств. Удалённые ранее записи требуют отдельной сверки с провайдером;
эта команда не может доказать отсутствие таких покупок.

## 3. Проверить выдачу на своей уже оплаченной покупке

В присланном логе ваша покупка имеет ID:

```bash
./venv/bin/python scripts/recover_paid_subscriptions.py --apply --invoice 32277abd-000f-5000-b000-1b46db3fc1db
```

Скрипт повторно сверяет оплату и не обрабатывает уже выданную покупку.
Перед изменением сохраняет JSON-копию платежа и всех подписок этого пользователя
в `payment-recovery-backup-ДАТА-ВРЕМЯ/` с закрытыми правами доступа.
Он добавляет только новую служебную таблицу активаций, не запускает общие
миграции/очистку схемы. По успеху показывает `ВЫДАНО` и отправляет ключ в бот.

Проверьте полученное сообщение и подключение по ключу. Если `НЕ ВЫДАНО` — бот
оставить остановленным и передать вывод; записи остаются для безопасного
повтора. Новый счёт оплачивать для теста не нужно.

## 4. Выдать остальные подтверждённые покупки

Только после успешной выдачи на предыдущем этапе и проверки списка:

```bash
./venv/bin/python scripts/recover_paid_subscriptions.py --since 2026-08-30 --apply --all-confirmed
```

По завершении ещё раз запустить проверку из пункта 2. Убедиться, что нет
подтверждённых оплат без выдачи и строк, требующих внимания. Если старое
продление, спорная привязка или ошибка API остались — не включать массовые
повторы до отдельной сверки.

## 5. Запустить бот после сверки

```bash
sudo systemctl start spn-bot
sudo journalctl -u spn-bot --since "2 minutes ago" --no-pager -n 100
```

Проверить свои подписки и следующую реальную покупку. Успех означает: статус
`paid` в базе, правильные срок/лимит в панели, ссылка в сообщении пользователю.
Одно только `systemctl active` или успешное чтение карты ID этого не доказывает.

## Локальные тесты

```bash
python3 -m unittest discover -s tests
```

Дополнительно SQL проверяется на изолированном PostgreSQL/WASM (PGlite 0.3.7),
без обращения к рабочей базе. Для этих необязательных тестов задать
`PGLITE_MODULE` — абсолютный путь к `@electric-sql/pglite/dist/index.js`.
Проверяются повторная выдача, архивирование пустых дублей, откат транзакции при
ошибке записи `paid`, сохранение оплаченных ГБ и однократное продление.
