# Российская точка проверки VPN

13 ноября 2026 года на VPS `83.141.70.86` установлен постоянный монитор;
14 ноября он обновлён до проверки актуальных конфигураций из Remnawave.
Клиентские ключи существующей тестовой подписки Admin переданы с явного
разрешения владельца. Секреты не включены в этот каталог.

Перед каждым циклом монитор получает актуальную тестовую подписку Admin,
включая отключённые хосты. Для каждого поддерживаемого VLESS-входа он запускает
отдельный Xray и выполняет HTTPS-запрос через VPN. Контрольный HTTPS-запрос
идёт через обычный интернет российского VPS: он не зависит от доступности
другого VPN-входа. Ошибка обновления подписки останавливает цикл и сохраняет
предыдущие приватные файлы.

В снимке от 14 ноября 04:16 UTC покрыты 26 из 34 записей; восемь записей
не поддерживаются преобразователем. Среди проверяемых есть отключённые
вручную хосты. Актуальные числа и причины пропуска находятся в `coverage.json`;
эти числа могут меняться после правок владельца в панели.

Установлены:

- код в `/opt/wayspn`;
- официальный Xray 26.7.28 в `/opt/xray/26.7.28/xray`;
- конфигурации `/var/lib/spn-ip-failover/refresh.json` и `routes.json`,
  владелец `spn-failover`, режим `0600`;
- результаты `/var/lib/spn-ip-failover/latest.json` и `coverage.json`, режим `0600`;
- `spn-controller-health.service` и включённый `spn-controller-health.timer`;
- отдельный официальный Chromium с Playwright в `/opt/wayspn/venv` для адаптера
  1Cent; платные операции пока не включены.

Таймер запускает следующую проверку через 120 секунд после завершения
предыдущей. Он включён для запуска после перезагрузки. Проверки выполняются
от отдельного пользователя `spn-failover`, одновременно проверяются до трёх
разных подключений. Публичный HTTP-сервис не открывался.

Предыдущий таймер `spn-probe-monitor.timer`, проверявший статический снимок
из 21 входа, отключён. Его приватные файлы сохранены для восстановления.

Проверен повторный автоматический цикл и отдельный запуск проверки через
SSH-ключ с принудительной командой. Приватный SSH-ключ и журнал установки
находятся в игнорируемом Git каталоге
`.local-state/ip-failover-ru-20261113/` на рабочем компьютере.

Состояние на сервере:

```sh
systemctl status spn-controller-health.timer
systemctl list-timers spn-controller-health.timer
journalctl -u spn-controller-health.service -n 20 --no-pager
cat /var/lib/spn-ip-failover/latest.json
```

Остановка с отключением автозапуска:

```sh
systemctl disable --now spn-controller-health.timer
systemctl stop spn-controller-health.service
```

В первых трёх циклах работали 16, 17 и 16 входов из 21. Дополнительная
проверка пяти неудачных входов показала доступность TCP-порта у всех пяти;
один из них при повторе успешно передал HTTPS через VPN. Эти результаты
не подтверждают блокировку IP. Из результата одной VPN-проверки нельзя
делать вывод о необходимости покупки адреса.

14 ноября польский VPS `2.26.148.130` подготовлен к назначению и переключению
IPv4 через ограниченный SSH-ключ контроллера. Исходная конфигурация ifupdown
сохранена в `/var/lib/spn-ip-failover-guest/bootstrap-original.interfaces`.
После успешного WS-теста на новом адресе исправлена устаревшая A-запись
`pol.tekst.site`: `144.31.171.189` → `2.26.148.130`. Это отдельное исправление,
не автоматическая покупка или ротация.

Автоматическая покупка, удаление IP и скрытие хостов ещё не включены.
Необходимы независимая внешняя проверка, проверенная привязка остальных VPS,
рабочий вход хостингов с контроллера и оплаченный пилот переключения.
Для проверки снаружи РФ выбран ограниченный SSH-ретранслятор на сервере
панели `144.31.170.147`; его установка ожидает рабочего root-доступа.
Клиентские ключи и учётные данные хостингов остаются на российском VPS.

Контроллер работает только пока сам российский VPS включён и оплачен.
Включение автопродления хостинга программой не выполнялось.
