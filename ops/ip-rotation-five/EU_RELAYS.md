# Ограниченные внешние проверки

install_eu_relays.py подготавливает только Эстонию и Германию из выбранных
пяти услуг. Это не новый VPN, не открытый SOCKS-сервер и не платная аренда.
Без --apply команда показывает локальный план, не читает пароли и не
открывает сетевые соединения.

При явно запущенном --apply:

1. Отдельные relay_<service UUID>_ed25519 создаются от spn-failover на
   российском контроллере. Приватные ключи остаются там; на Mac и в EU
   передаётся только публичная часть.
2. На нужном VPS проверяется служебная .service-id. Создаётся отдельный
   непривилегированный spn-ip-relay с заблокированным паролем и приватным
   каталогом /var/lib/spn-ip-relay.
3. Только для него добавляется
   /etc/ssh/sshd_config.d/91-spn-ip-relay.conf: локальное TCP-перенаправление
   на порт 443, без удалённых listener, Unix-сокетов, tunnel, PTY, agent, X11
   и парольной аутентификации. Любая команда принудительно заменяется
   /usr/bin/false.
4. Проверяются sshd -t, точные настройки нового пользователя и байтовое
   совпадение эффективной конфигурации root до/после. Только затем допустим
   systemctl reload ssh; перезапуск SSH, сети и VPN не используется.
5. Ключ с ограничением источника 185.9.24.53, restrict, port-forwarding,
   permitopen на порт 443 и принудительной /usr/bin/false публикуется лишь
   после загрузки ограничений. Сохраняются резервные копии и журнал установки
   в /var/lib/spn-ip-relay-setup.

Чужой пользователь с таким именем, чужой drop-in или другие опции того же
публичного ключа не перезаписываются. При неподдерживаемом Match либо
изменении настроек root новый drop-in удаляется **до reload**. При потере
ответа на reload ключ ещё не опубликован; повтор может безопасно закончить
установку. Предыдущий идентичный drop-in не удаляется автоматически.

Ограничение *:443 задаёт порт, но **не изолирует приватные сети** и не разрешает
обход политик доступа к ним. Внешний проверяющий клиент обязан отдельно
разрешать только публичные IP назначений; эту проверку выполняет
spn_ip_failover.relay_worker. Нельзя передавать этот ключ произвольному
пользовательскому SOCKS-клиенту.

План не доказывает работоспособность. После установки требуется реальная
SSH/SOCKS-проверка с российского контроллера, включая отказ для порта не 443
и запрет shell/PTY. Только затем внешний маршрут можно включать в принятие
решений об автопокупке IP.
