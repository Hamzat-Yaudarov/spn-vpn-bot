# Замена IPv4 VPN-ноды

Один скрипт для VPS на Linux с одним простым IPv4-маршрутом. Требуются
Python 3.8+, `ip` из iproute2 и `curl`. Он не назначает IP, не меняет DNS или
Remnawave, не устанавливает службы и не перезапускает сеть или Xray.

## На каждой VPS

Сначала добавь новый IPv4 у хостера, оставь старый и проверь SSH по новому
адресу. Если SSH показывает изменившийся ключ уже известного адреса, сначала
сверь его с хостером или через веб-консоль. Из папки репозитория на Mac:

```sh
scp ops/ip-move/ip_move.py root@НОВЫЙ_IP:/root/ip_move.py
ssh root@НОВЫЙ_IP
```

На VPS (подставь IPv4 в обе строки):

```sh
python3 /root/ip_move.py НОВЫЙ_IP
python3 /root/ip_move.py НОВЫЙ_IP --apply
```

Без `--apply` команда только читает локальные настройки. При применении
скрипт проверяет HTTPS с новым адресом, сохраняет прежний маршрут в
`/root/spn-ip-move-*`, затем проверяет DNS и HTTPS уже без привязки к адресу.
Если проверка не проходит, он возвращает прежний маршрут, пока тот не был
изменён другим процессом. Сохрани доступ к консоли хостера на случай обрыва SSH.

### Сохранение после перезагрузки

- Для **уже настроенного ifupdown**, как на Эстонии `vds100269`, добавь
  `--ifupdown` к **обеим** командам. Скрипт должен найти нужный статический
  алиас с известным `post-up ... onlink src`. Тогда он заменит только его
  адрес и `src`, проверит через `ifquery` и сохранит оригинал в резервной копии.
- Без `--ifupdown` меняется **только текущий маршрут**. Его может сбросить
  перезагрузка, DHCP или сетевой менеджер. Постоянный адрес и исходящий маршрут
  на такой VPS настраивай средствами хостера или её сетевого менеджера. Не
  добавляй ifupdown-алиас наугад на VPS с Netplan или cloud-init.
- Скрипт откажется менять сеть при нескольких маршрутах, особых правилах
  маршрутизации, другом интерфейсе или публичном IP, которого нет в ОС.

## После проверки HTTPS

1. В Remnawave обнови адрес **ноды**, сохранив её порт. Если хост публикует IP
   напрямую — замени и его адрес, не трогая порт, SNI, ключи и профиль.
2. Если хост публикует домен — замени его старую A-запись, не добавляя вторую.
   Для CDN с IP в источнике обновляется только адрес источника, а клиентский
   CDN-домен остаётся тем же.
3. Обнови подписку и проверь открытие сайтов через каждый изменённый хост из
   сети, где ими пользуешься. `HTTPS 204` в скрипте проверяет выход **самой
   VPS**, но не доказывает доступность VPN с телефона. Удаляй старый IPv4
   только после этой проверки и обновления DNS.
