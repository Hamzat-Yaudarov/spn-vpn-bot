# Румыния: дополнительный порт 8443

VPS: `82.152.132.35`, deployment `96f1989a670c46178ab81b24da941aa7`.

Владелец сам разрешил 8443 в UFW и изменил публичный порт хоста в панели.
Добавлена отдельная служба `spn-reality-alt8443.service`:

- конфигурация `/etc/haproxy/spn-reality-alt8443.cfg`;
- `0.0.0.0:8443` → PROXYv2 → прежний Xray `127.0.0.1:2443`;
- автозапуск включён, исходный HAProxy на 443 не изменён и не перезапускался;
- профиль, инбаунд, ключи, пользователи и записи панели не менялись.

Проверки 17 ноября 2026:

- REALITY через временный SSH-канал проходит HTTPS и проверку выходного IP
  на обоих портах; временные клиенты/SSH-каналы закрыты.
- Прямые проверки с физического en0 не проходят. Последняя серия: TCP22,
  TCP443 и TCP8443 — таймаут; контрольные `1.1.1.1:443` и
  `144.31.170.147:443` доступны через тот же en0.
- Через действующий VPN Mac SSH к VPS работает; обе службы и оба слушателя
  подтверждены активными. Это указывает на зависимость от сетевого пути,
  а не доказывает конкретного оператора/источник фильтрации.
- Chrome/Firefox и локальная сегментация не дали успешного прямого теста.
  Для сегментации даже внешнее TCP8443 не установилось, поэтому результат
  не доказывает неэффективность самой сегментации при доступном TCP.
- Владелец подтвердил, что после обновления подписки сайты всё ещё не открываются.

VPS не перезагружалась и не переустанавливалась. Сохранённый план
универсального установщика остаётся исходным планом 443; пользовательское
изменение хоста на 8443 не переписывалось автоматически.
