# Обход через арендованное VK-реле

Скрипт настраивает чистую Ubuntu 24.04 и создаёт в Remnawave один профиль,
инбаунд, ноду и хост. Протокол — TCP REALITY / Vision, Safari. Названия получают
случайный код из 6 букв и цифр; повтор запуска сохраняет код и ключи.

Домен, DNS и сертификат не нужны. Аренду VK оплачиваешь и переключаешь сам:
скрипт не покупает её и не управляет ботом арендодателя.

## Что указать при аренде

Адрес назначения у арендодателя:

```text
IP_ВАШЕЙ_VPS:443
```

Именно **443**, не `2443`. Установка использует защищённый вход HAProxy на 443;
внутренний Xray слушает только `127.0.0.1:2443`.

После аренды получишь внешний адрес вида `IP_РЕЛЕ:ПОРТ`. IP и порт могут быть
любыми выданными арендодателем публичными IPv4 и TCP-портом — они не зашиты
в скрипт. Нужна аренда с обычной прозрачной передачей TCP, без завершения TLS
и без добавления PROXY-заголовка со стороны арендодателя.

## Запуск на Mac

Замени три значения: IP своей VPS, внешний адрес аренды и название.

```bash
python3 ~/Downloads/SPNvpnF/ops/universal-vk/deploy.py \
  --ip IP_ВАШЕЙ_VPS \
  --relay IP_РЕЛЕ:ПОРТ \
  --name "🇩🇪 Германия" \
  --country DE \
  --apply
```

Например, внешний адрес аренды `185.86.147.77:10038` передаётся целиком:
`--relay 185.86.147.77:10038`. Это не адрес собственной VPS.

Сквады выбираются при запуске; можно заранее указать `--squad bypass`.
Пароль VPS вводится только в запросе SSH. Настройки панели читаются из `.env`;
API-токен панели на VPS не передаётся. Без `--apply` показывается только план.

В ноде панели остаётся **IP собственной VPS**, а в хосте подписки —
**IP и порт арендованного реле**. После успешной проверки обнови подписку
в Happ/INCY.

По умолчанию SNI — `login.vk.com`, как в прежних VK-подключениях. Если твой
арендодатель разрешает другой SNI, можно явно указать
`--sni www.cloudflare.com`. SNI клиента и сервера согласуются скриптом.

## Если выдали другой IP или порт аренды

На той же VPS повтори команду с новым внешним адресом:

```bash
python3 ~/Downloads/SPNvpnF/ops/universal-vk/deploy.py \
  --ip IP_ВАШЕЙ_VPS \
  --relay НОВЫЙ_IP_РЕЛЕ:НОВЫЙ_ПОРТ \
  --apply
```

Сначала направь новую аренду на `IP_ВАШЕЙ_VPS:443`. Скрипт обновляет только
собственный хост, сохраняя ключи, код и UUID ноды, профиля и инбаунда.
Вторую ноду для той же VPS не создаёт. Название, страну, сквады и SNI при
продолжении можно не повторять — используются сохранённые значения.

После прерывания повтори ту же команду. Если меняешь IP самой VPS, это уже
другой адрес установки, а не смена аренды.

Если незавершённая аренда уже истекла, просто передай новый `--relay`.
После входа по SSH скрипт сверит прежнюю операцию и её собственный хост,
восстановит последнее подтверждённое состояние и проверит новую аренду.
Истёкший адрес не нужно заставлять проходить проверку или вручную удалять файлы.
При неудачной новой проверке предыдущий подтверждённый хост не заменяется.

## Проверка и ограничения

Проверка подключается именно через `IP_РЕЛЕ:ПОРТ` и сверяет выходной адрес
с IP твоей VPS. Просто открытого порта недостаточно.

- `--test-route auto` — сначала прямой путь через физический интерфейс Mac,
  затем текущее системное подключение, если первый тест не прошёл.
- `--test-route physical` — только прямой путь; по умолчанию интерфейс `en0`.
- `--test-route system` — через текущее подключение Mac, в том числе уже
  работающий VPN. Это не доказывает доступность у мобильного оператора.
- `--test-route ssh` — проверяет только backend через SSH. Новый хост остаётся
  подготовленным, но не публикуется как проверенный обход. Позже повтори
  команду с `auto`, `physical` или `system` для проверки самого реле.

Для реального теста используется уже предоставленная подписка из приватного
файла `~/Downloads/SPNvpnF/.vpn-test-link.txt`. Новые пользователи, покупки
и балансы не создаются.

Установка VK и обычная REALITY-установка используют общее состояние backend,
чтобы не создавать два контроллера одной VPS. Если эта VPS уже настроена
в другом режиме, скрипт остановится: он не превращает обычный сервер в обход
и не удаляет чужие службы без отдельного решения.

Сохраняй `~/.spn-reality-deploy/` и всю папку проекта, а не только этот файл:
используются общие модули установщика REALITY. Не публикуй приватное состояние.

Скрипт не гарантирует, что выданный IP действительно доступен при белых списках
у каждого оператора. Это зависит от аренды и сети. Скорость также ограничена
оплаченной полосой реле и каналом VPS; установка не делает её безлимитной.

Локальные тесты (без настоящих покупок, SSH и панели):

```bash
cd ~/Downloads/SPNvpnF
python3 -m unittest discover -s ops/universal-vk -p 'test_*.py'
```
