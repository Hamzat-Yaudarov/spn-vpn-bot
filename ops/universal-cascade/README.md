# Каскад: пользователь → RU → EU → интернет

Вход — один TCP REALITY / Vision / Safari на российском сервере. RU передаёт
нерасшифрованный поток через зашифрованный WireGuard-туннель на EU. VLESS
пользователя обрабатывается на EU, интернет-трафик выходит там же.

В подписке только RU-домен. На EU VPN-инбаунд доступен лишь на приватном IP
туннеля, а порт управления нодой — только с IP панели Remnawave. RU не получает
REALITY private key, служебный ключ Remnawave или пользовательские ключи.
При обрыве туннеля нет резервного выхода напрямую через RU.

## Что означает «скрыть EU-IP»

EU не указан как адрес подключения в подписке и не виден провайдеру клиента
как прямое назначение соединения. Но сайты **и сам пользователь при проверке
внешнего IP** увидят выходной EU-IP. Хостинг RU может видеть EU как адрес
WireGuard-пира. Это не анонимизация от всех сторон и не гарантия обхода белых
списков: RU-IP должен быть доступен в сети клиента.

## Требования

- Для первого каскада — две **разные чистые Ubuntu 24.04 VPS** с публичными
  IPv4, root-доступом по SSH и разрешённым исходящим интернетом. Для следующих
  выходов используется тот же настроенный RU и новая чистая EU VPS.
- Не использовать рабочие VPS с другими VPN/контейнерами/сервисами. Скрипт
  не сносит их и остановится при конфликте. `185.9.24.53` с контроллером —
  не чистая VPS для этой установки.
- Предустановленный агент мониторинга Zabbix на TCP 10050 допускается после
  проверки пакета, исполняемого файла и службы. Скрипт не останавливает его и
  сохраняет доступ к его порту. Произвольный сервис на 10050 исключением не считается.
  Если служба хостинга не распознаётся, но ты хочешь её оставить, добавь
  `--ru-keep-tcp-port 10050` для RU или `--eu-keep-tcp-port 10050` для EU.
  Это явное разрешение оставить TCP 10050 открытым без проверки типа службы;
  скрипт не меняет, не останавливает и не перезапускает эту службу. Исключение
  сохраняется для повторных запусков и автоматически наследуется новыми ветками
  того же RU. Другие порты и службы этим параметром не разрешаются.
- UDP между VPS: на новых EU — 443 (можно задать `--eu-wg-port`); на RU у каждой ветки свой UDP-порт
  (по умолчанию совпадает с её входным TCP-портом). Внешний firewall хостинга
  должен разрешать эти UDP-порты между соответствующими IP. Firewall гостевых
  ОС настроит скрипт. TCP и UDP одного номера не конфликтуют.
- Прежний локальный проект SPN с настройками API Remnawave, действующая
  проверочная подписка `.vpn-test-link.txt` с правами 0600, Python с
  `cryptography`. Автотест на Mac Apple Silicon, как в прежних установщиках.
- API-токен Cloudflare: Zone DNS Edit + Zone Read только для своей зоны.
  Он остаётся на Mac. Для первого сохранения:

```bash
python3 ~/Downloads/SPNvpnF/ops/universal-reality/setup_cloudflare.py
```

## Одна команда на Mac

```bash
python3 ~/Downloads/SPNvpnF/ops/universal-cascade/deploy.py \
  --ru-ip RU_IP \
  --eu-ip EU_IP \
  --name "🇳🇱 Нидерланды • каскад" \
  --country NL \
  --apply
```

Замени `RU_IP` и `EU_IP` настоящими адресами. Страна/название описывают выходной
сервер. Сквады выбираются при запуске; можно передать `--squad regular`.
Вводятся пароли **обеих** VPS в стандартных запросах SSH. Сохранённые SSH-ключи
не удаляются; изменённый ключ после переустановки требует явного подтверждения.

Домен `c-<случайный_код>.wayspn.com` создаётся автоматически: **одна DNS-only
A-запись, только на RU**, TTL 60. Для своего свободного имени добавь
`--domain cascade1.wayspn.com`. Для другой зоны — `--dns-zone example.com` и
токен с доступом к ней. EU-домен и сертификаты не нужны. SNI — `www.cloudflare.com`.
Cloudflare не проксирует трафик, только хранит DNS.

## Один RU-IP для нескольких EU

Первый запуск занимает TCP 443 на RU. Для второй EU повтори команду с тем же
`--ru-ip`, но новым `--eu-ip` и названием:

```bash
python3 ~/Downloads/SPNvpnF/ops/universal-cascade/deploy.py \
  --ru-ip RU_IP \
  --eu-ip SECOND_EU_IP \
  --name "🇩🇪 Германия • каскад" \
  --country DE \
  --apply
```

Скрипт сам выберет свободный входной порт: 443, затем 8443 и далее. Можно явно
задать `--entry-port 8443`. Отдельный RU UDP-порт задаётся `--ru-wg-port`, если
нужно; обычно этот параметр не требуется. Занятый порт не перезаписывается.

При сохранённом локальном состоянии скрипт повторно использует RU-домен и
подтверждённую DNS-запись: например, `c-xxxxxx.wayspn.com:443` ведёт на первую EU,
а тот же домен с `:8443` — на вторую. У каждой EU свои профиль, нода, хост, ключи,
WireGuard-интерфейс и отдельная служба на RU. Добавление новой ветки не
перезапускает службы старых. При выборе другого `--domain` будет создана
отдельная DNS-only запись на тот же RU-IP.

Старый одиночный каскад также поддерживается: его порты 443/51820, ключи и
службы сохраняются. Для подтверждения владения нужны его исходные локальные
файлы в `~/.spn-cascade-deploy/`. Если использовался `--state-dir`, храни состояния
веток в соседних каталогах одного родителя. Одновременно на одном RU добавляется
только одна ветка; после прерывания сначала повтори её команду.

Профиль, нода и хост создаются в Remnawave автоматически с одним случайным
кодом из 6 букв/цифр. В панели управление нодой указывает на EU-IP; это
административные данные, не адрес в пользовательской подписке.

## Проверка и повтор

Перед изменениями проверяются обе VPS и отсутствие чужих сервисов либо
подтверждённое владение уже настроенными ветками RU. Ключи
WireGuard и REALITY сохраняются локально; конфигурация каждой роли содержит
только её секреты. Сеть и SSH не перезапускаются. Нет NAT, глобального
IP-forwarding или default route через туннель; у WireGuard только маршруты /32
к его единственному пиру. Для дополнительного IPv4 может быть выбран и сохранён
предпочтительный исходящий адрес прежним проверенным helper-скриптом.

Перед включением хоста должны пройти: свежий handshake WireGuard, проверка
firewall/приватного EU-слушателя и девять настоящих VPN-запросов через RU с
выходом именно EU IPv4. Затем хост включается для проверки фактической выгрузки
RU-хоста в подписке; если она не пройдёт, только что включённый хост выключается.
Открытого SSH или цифры пинга недостаточно. Это проверка текущего пути, не
обещание постоянной доступности IP у всех операторов.

По умолчанию тест привязывается к физическому `en0` и не переключает VPN Mac.
Если интерфейс другой, укажи `--interface en5`. При необходимости можно явно
добавить `--test-route system`: проверка пойдёт через текущую сеть Mac,
возможно через другой VPN, и **не подтвердит прямую доступность RU**.
SSH-подмена транспортного теста для этого каскада не применяется.

После ошибки или переустановки той же пары VPS повтори **ту же команду**.
Имена, UUID и ключи не создаются заново. Автопринятия изменившихся SSH-ключей
нет. Не удаляй `~/.spn-cascade-deploy/`: это закрытое состояние установки,
сделай защищённую резервную копию.

Этот скрипт не является заменой IP готового каскада. При изменении RU/EU-IP
меняются также WireGuard endpoint и firewall — **одной правки DNS недостаточно**.
Другие наши прямые сервера, VK/CDN-обходы и программа Voxa не затрагиваются.

### Если старый каскад не устанавливает WireGuard handshake

На одном из проверенных маршрутов ответы на UDP 51820 не доходили до EU,
а с UDP 443 туннель и настоящий VPN-трафик проходили. Поэтому новые установки
используют EU UDP 443. Это наблюдение конкретного маршрута, не гарантия для всех
хостингов и операторов. Внешний firewall хостинга также должен разрешать UDP 443.

У существующего format-2 каскада можно отдельно сменить только UDP-порт EU,
не пересоздавая ноду, профиль, хост или ключи:

```bash
python3 ~/Downloads/SPNvpnF/ops/universal-cascade/repair_udp.py \
  --ru-ip RU_IP --eu-ip EU_IP --eu-wg-port 443 --apply
```

Используется исходное локальное состояние. Перед изменениями сохраняются
защищённые резервные копии. Меняются только параметры этого туннеля и его
точное правило UDP на EU; службы сети, Xray и соседних каскадов не перезапускаются.
При обычной ошибке до фиксации плана программа откатывает завершённые шаги.
После ремонта повтори исходную команду `deploy.py --apply`, чтобы проверить
настоящий VPN-трафик и подписку. Резервные файлы могут содержать секреты
WireGuard: не присылай их в переписку и не публикуй.

Без `--apply` команда печатает только план, без сети и изменений. Проверка кода:

```bash
python3 -m unittest discover -s ~/Downloads/SPNvpnF/ops/universal-cascade -p 'test_*.py'
```

## Ограничения скорости

Скорость ограничена самым узким из каналов клиент→RU, RU→EU и EU→интернет,
а также CPU и количеством соединений. Все EU за одним RU делят его канал,
CPU и единый входной IP: отказ или блокировка RU затронет все эти ветки.
Дополнительный RU-hop может увеличить
задержку. Скрипт не покупает серверы, IP, CDN и не гарантирует обход ограничений.
