# Создание сервера и замена VPS

Команды запускаются **на Mac**, не внутри SSH. Покупку, бесплатную замену IP
у хостинга и удаление VPS выполняешь сам. Скрипты не обращаются к биллингу.

## Один раз: Cloudflare

API Token: **Zone / DNS / Edit** и **Zone / Zone / Read**, только зона
`wayspn.com`. Пароль аккаунта и Global API Key не нужны. Сохрани токен локально,
скрытым вводом, не в чате:

```bash
python3 ~/Downloads/SPNvpnF/ops/universal-reality/setup_cloudflare.py
```

Токен остаётся на Mac в `~/.config/spn/cloudflare-token` с правами 0600.
Для другой зоны нужен доступ к ней и `--dns-zone` при первом создании.

## 1. Первое создание

Выбери свободный домен для этого сервера. У каждого сервера свой постоянный домен.
Пример:

```bash
python3 ~/Downloads/SPNvpnF/ops/universal-reality/deploy.py \
  --ip НОВЫЙ_IP \
  --domain fi1.wayspn.com \
  --name "🇫🇮 Финляндия" \
  --country FI \
  --apply
```

Скрипт создаёт профиль, один инбаунд, ноду и хост, а также DNS-only A-запись
с TTL 60. Если `--domain` пропустить, домен выбирается автоматически и печатается
в конце. Новые установки используют TCP TLS с сертификатом постоянного домена.
Сохранённые REALITY-установки продолжают использовать свой протокол.

## Смена IP на той же VPS

Сначала добавь резервный IPv4 **к этой же VPS у хостера** и проверь, что SSH
доступен на новом адресе. IP должен присутствовать в гостевой ОС и сохраняться
там после перезагрузки. Для ручного переключения с достаточной тебе проверкой
по SSH:

```bash
python3 ~/Downloads/SPNvpnF/ops/universal-reality/change_ip.py \
  --domain de11-1-1.wayspn.com \
  --ip НОВЫЙ_IP \
  --ssh-only \
  --apply
```

Скрипт проверяет прежний SSH-ключ, machine-id и установленную ноду; меняет
исходящий IPv4 с сохранением после перезагрузки, обновляет прежнюю DNS-запись
и управляющий адрес ноды. Домен, UUID, профиль и TLS-сертификат сохраняются.
Сервисы VPN и сеть не переустанавливаются. Старый IP не удаляется.

`--ssh-only` пропускает девять VPN-тестов, Xray на компьютере и тестовую
подписку. Успех означает SSH-доступность и проверку настроек; VPN-трафик в
журнале не помечается проверенным. Без этого флага выполняются прежние
полные VPN-тесты. Монитор панели использует `--ssh-only --non-interactive`:
для этого нужен вход root по SSH-ключу/агенту и настроенные локальные токены
Remnawave и Cloudflare. Пароли интерактивно не запрашиваются.

Проверка проходит из сети машины, запускающей команду. Для обнаружения
нужной блокировки выключи VPN и используй сеть без действующих белых списков.
После DNS-переключения команда ждёт прежний TTL 60 секунд; пользователям
может потребоваться переподключение.

Если команда прервалась, повтори тот же домен, IP и режим `--ssh-only`.
Незавершённая операция не переключается на другой резервный адрес.

## 2. Замена старой VPS новой

Полная замена поддерживается для управляемых установок **TLS** и **REALITY**.
Для TLS установщик выпускает сертификат прежнего домена через Cloudflare DNS-01
до переключения A-записи. На машине, запускающей перенос, нужны `certbot`,
`openssl` и `dig`. Сохраните прежний SSH-порт.

Ты арендуешь новую **чистую Ubuntu 24.04** и проверяешь доступность её IP.
Отклик SSH не доказывает, что доступен VPN-порт 443; это отдельно проверит скрипт.
Для существующего `fi1.wayspn.com`:

```bash
python3 ~/Downloads/SPNvpnF/ops/universal-reality/replace.py \
  --domain fi1.wayspn.com \
  --ip НОВЫЙ_IP \
  --apply
```

Меняешь только домен нужного сервера и новый IP. Новый домен придумывать не нужно.
Пароль новой VPS вводится в запросе SSH, не сохраняется и не передаётся в панель.
При первом подключении подтверждается SSH-ключ; после переустановки изменённые
ключи не принимаются без явного подтверждения. VNC не является обязательным.

Скрипт:

1. Находит по домену ровно одну завершённую локальную установку и проверяет
   её UUID в панели, ключи и владение существующей DNS-записью.
2. Устанавливает на новую VPS ту же ноду с тем же служебным ключом. Новые
   профиль, инбаунд, нода, хост и пользователи не создаются; сквады не меняются.
3. Временно направляет управление **существующей** нодой на новый IP, чтобы
   панель передала ей прежнюю конфигурацию; проверяет настоящий VPN-трафик.
4. Меняет только IP у прежней A-записи с тем же ID. Проверяет DNS и возвращает
   адрес управления нодой на прежний домен. После правки ждёт истечения прежнего
   TTL 60 секунд, чтобы панель не подключилась обратно к закэшированному старому IP.
5. Проверяет итоговую конфигурацию и выгрузку подписки, сохраняет результат.

По умолчанию проверяется прямой путь с физического интерфейса Mac (`en0`).
Если физический интерфейс другой, укажи `--interface en5`. Если включены белые
списки, можно явно выбрать `--test-route ssh`: это проверит настройку через SSH,
но **не подтвердит прямую доступность нового IP**. Системный VPN скрипт не
переключает. Нужна прежняя действующая тестовая подписка в приватном файле
`.vpn-test-link.txt`, как для первого установщика.

У пользователей остаётся тот же хост и подписка; может потребоваться
переподключение из-за разрыва старых соединений и DNS-кэша. Мгновенного
переключения без перерыва не обещается.

## Если выполнение прервалось

Повтори **ту же команду замены с тем же доменом и IP**. Прогресс сохраняется;
UUID и ключи не генерируются заново. Начатая замена блокирует запуск первого
установщика для старой установки, чтобы тот не вернул прежний адрес.
Незавершённую операцию нельзя молча переназначить на другой IP: сначала нужно
закончить или отдельно разобрать именно её. Флага отмены пока нет; журнал
вручную не удаляй, иначе потеряется информация о промежуточном состоянии.

Если ответ Cloudflare потерялся, повтор сначала читает состояние прежней
записи, а не отправляет новую запись или повторную неподтверждённую правку.
Если результат правки неизвестен и DNS всё ещё старый, скрипт остановится:
проверь именно эту запись в Cloudflare, не удаляй её и не очищай локальный журнал.
Не меняй запись вручную параллельно с работающей командой.

В случае ошибки после переключения скрипт не возвращает DNS автоматически на
старую VPS: её могло уже не существовать. Продолжай ту же операцию. Покупки,
удаления VPS и автоматического отката на удалённую VPS здесь нет.

## Важное про сохранённые данные

Не удаляй `~/.spn-reality-deploy/`. Там хранятся ключи, доказательства владения
UUID и DNS-записью и история замен. Без этих данных нельзя безопасно выбрать
сервер только по совпавшему имени в панели. Для нестандартного расположения
исходной установки используй `--state-dir /путь/к/её/папке`.

Старые IP-only установки и VK-обходы автоматически не мигрируются. Для замены
по домену сначала нужна завершённая установка именно доменной версии `deploy.py`.
Существующую запись чужого происхождения скрипт не принимает за свою.

Без `--apply` обе команды показывают только план, без сетевых запросов и изменений.
