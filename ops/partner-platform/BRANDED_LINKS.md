# Ссылки и единая панель партнёров

Согласованный адрес: `https://<slug>.sub.wayspn.online/<личный-токен>`.
Токен уникален для подписки и криптографически связан с проектом, поддоменом
и версией отзыва. В нём нет Telegram ID. Поддомен сам по себе не авторизует.

## Что открывается

- Обычная навигация браузера и запрос с `Accept: text/html` открывают страницу
  с названием/логотипом/цветом/поддержкой партнёра.
- Нативный запрос Happ/Happ Plus/INCY и обычный запрос конфигурации получают
  конфиг, не HTML и не редирект на основной SPN. Передаются реальные заголовки
  приложения/устройства; HWID не подставляется и ограничения не отключаются.
- Копирование и Happ-import используют одну каноническую ссылку. Ответ содержит
  партнёрский `profile-title`; `profile-web-page-url` ведёт на его страницу.
- `/<token>/config` остаётся явным вариантом для конфигурации. Прежние маршруты
  `/s/<token>` (всегда HTML) и `/s/<token>/config` также сохранены без редиректов.
- Котировка и продление доступны на `/<token>/purchase-quote` и
  `/<token>/purchases/...`; POST по-прежнему требует того же HTTPS Origin,
  подтверждённой цены и неизменного request key.

Выбор HTML/конфига — только формат ответа, **не проверка личности**. Для обоих
вариантов одинаково проверяются Host, подпись, проект и состояние подписки.
Нельзя выбирать чужой проект через query, Cookie или X-Forwarded-Host.
Все ответы private/no-store/no-referrer. Пути с токеном не должны попадать
в access/error logs, аналитику, CDN-кеш и трассировки.

`PartnerLinkSettings(short_links=True)` включает новый формат. Старый формат
по умолчанию сохранён для совместимости программных вызовов. Независимый runtime
новой платформы использует короткий формат. Стиль пути не меняет подпись; смена
самого base_domain или signing key меняет ссылки и требует отдельного решения.

## DNS/HTTPS: основной sub не трогаем

Публикация отдельно согласовывается. Понадобятся:

1. Wildcard DNS **`*.sub.wayspn.online`** на отдельный партнёрский шлюз.
2. Сертификат именно для **`*.sub.wayspn.online`** с автоматическим DNS-01
   продлением. Сертификат `*.wayspn.online` этот уровень не покрывает.
3. Отдельный управляющий адрес, например `partners.wayspn.online`, и имя
   управляющего Telegram-бота в защищённой конфигурации runtime.

Запись `sub.wayspn.online`, основной SPN и его существующие короткие ссылки
не перенаправляются на новый шлюз. Неизвестные поддомены отклоняются. Общая
Remnawave не должна быть напрямую опубликована через wildcard партнёров.

## Учёт и поддержка

Все VPN-пользователи создаются одной явно выбранной панелью Remnawave.
В отдельной базе партнёров хранится связь проект → клиент → подписка → UUID
Remnawave. Пользовательские ссылки никогда не строятся из Telegram ID.

Миграция `panel_identity.sql` сохраняет прежние технические имена существующих
подписок, включая возможные незавершённые создания. Новые читаемые идентификаторы
включаются отдельно через `panel_identity_enabled`: имя/метка проекта, Telegram
ID клиента и описание бренда/бота. Служебный снимок сохраняется до первого
запроса в Remnawave и используется при повторах/продлении/проверке трафика,
поэтому переименование бренда не создаёт вторую подписку. Ручное редактирование
служебных полей в панели требует отдельного согласованного инструмента сверки.

Владелец платформы видит записи всех франшиз в одной панели; партнёры получают
доступ только к своим данным в кабинете, но не ключ администратора Remnawave.

## Проверка перед выпуском

Локальные тесты покрывают маршруты, заголовки браузера и клиентов, legacy aliases,
отзыв ссылки, чужой Host, запрет конфигурации для истёкшей/непроверенной подписки,
повтор оплаты и сохранение идентичности. Настоящие импорт/обновление и открытие
страницы из Happ/INCY на телефоне всё равно проверяются на отдельном стенде:
фикстура User-Agent не является доказательством поведения установленного клиента.
