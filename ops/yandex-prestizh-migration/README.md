# PRESTIZH: перенос одного CDN-подключения на Yandex

Разрешён только хост `645c8877-c1ef-4224-993d-70a31b5cd4e5`, его CDN inbound
`vless-xhttp-vk-prestizh` и XHTTP-настройки в существующем профиле
`63c21878-f375-4383-af21-98c777c358c5`. Имя профиля сохраняется.
Прямые gRPC, WS, Hysteria2, ноды, сквады, пользователи и остальные хосты не меняются.

Источник — проверенный Yandex DE11: профиль
`59aba40b-9ed3-4eec-b6af-b34a39da88d1`, inbound `vless-xhttp-yandex-de11`,
хост `c1614c56-403d-4a67-b917-928a04600db8`.
Копируются только серверные `xhttpSettings` и клиентские `xhttpExtraParams`.
Серверный path заменяется существующим PRESTIZH path; адрес `cdn.prestizh.site`,
Host, SNI, ALPN, порт и остальные поля хоста сохраняются.
Не подставляйте старые direct `packet-up` или VK GET/body параметры:
DE11 использует GET/header, `X-Transport-Data`, пакет не более 2048 байт,
server header limit 8192 байта.

## Порядок

1. Через кабинет Yandex отдельно подготовить разрешённый CDN-ресурс, корректные
   origin HTTPS/Host/SNI, edge-сертификат и CNAME. Проверить ограничения методов,
   сохранение транспортного header и размера, отсутствие кеширования/буферизации
   туннеля. Проверить origin ACL. Эти действия данный helper не выполняет.
2. Выполнить `python3 ops/yandex-prestizh-migration/manage.py prepare`.
   Это только GET `/config-profiles`, `/hosts`, `/nodes`; пользовательские endpoints
   не читаются. Команда печатает путь новой приватной директории `/private/tmp/…`.
3. Проверить `validation-profile.json` штатной проверкой совместимой версии Xray.
   Это отдельная копия с `settings.clients=[]`, без подписчиков. Серверные REALITY
   ключи других inbound остаются в приватном файле для проверки конфигурации;
   не выводите и не публикуйте JSON. `candidate-profile.json` не очищает и не меняет
   исходные settings прямых подключений.
4. После проверки CDN/DNS/TLS и согласования момента переключения выполнить
   `python3 ops/yandex-prestizh-migration/manage.py audit /private/tmp/…`.
5. Только при готовности выполнить
   `python3 ops/yandex-prestizh-migration/manage.py apply /private/tmp/… --confirm`.
   Это две записи: PATCH выбранного профиля с config и PATCH выбранного хоста
   исключительно с `xhttpExtraParams`. Перед первой записью и между записями
   выполняется GET-аудит. API не предоставляет compare-and-swap: не редактируйте
   панель параллельно в коротком окне GET→PATCH.
6. Повторить GET-аудит и проверить полноценное подключение тестового клиента
   после обновления подписки. HTTP 200/400 или один handshake не доказывают
   прохождение VPN-трафика. Публичное включение других хостов не входит в перенос.

## Сбой или конкурентные изменения

Записи не повторяются автоматически. При timeout/ошибке helper не печатает тело
HTTP-ответа или конфигурацию. Сначала выполните `audit`:

- `prepared`: обе настройки исходные;
- `profile_applied`: профиль уже переключён, клиентские extras ещё исходные;
- `complete`: обе настройки подтверждены свежим GET.

При подтверждённом `profile_applied` следующая явно разрешённая команда `apply`
с тем же каталогом выполнит только недостающую запись хоста. Изменение любого
другого хоста, профиля, прямого inbound, node binding, выбранного path/домена или
неожиданный host-only partial state останавливает работу. Не обходите guards
редактированием manifest. Автоматического rollback, создания нод/сквадов,
перевыпуска пользовательских ключей и SSH в helper нет.

## Ограниченный явный rollback

Если требуется вернуть только настройки Remnawave, сначала выполнить `audit`
того же каталога и проверить актуальные DNS/CDN. Затем явно выполнить
`python3 ops/yandex-prestizh-migration/manage.py rollback /private/tmp/… --confirm`.
Команда восстанавливает **только** прежний `xhttpExtraParams` выбранного хоста,
затем прежний config выбранного профиля из сохранённого снимка. Используются те же
проверки неизменности всех остальных объектов и свежий GET между записями;
неопределённый результат записи не повторяется автоматически. После сбоя сначала
повторить `audit`, затем явно разрешённый `rollback` с тем же snapshot.

Rollback не меняет CNAME, сертификаты, origin ACL или Yandex-ресурс и не делает
заблокированный VK-ресурс рабочим. Если DNS уже указывает на Yandex, восстановление
старого транспорта само по себе не означает восстановление связи. При любом
постороннем drift требуется остановиться; старым снимком нельзя затирать чужие
изменения. Скрипт не выполняет откат инфраструктуры автоматически.

## Приватные файлы

Каталог имеет права 0700, JSON — 0600; файлы создаются эксклюзивно.
Полные профили содержат серверные секреты. Храните snapshots только вне Git
в `/private/tmp`, не добавляйте их в репозиторий и не отправляйте содержимое в чат.
Manifest содержит хеши файлов; загрузка повторно проверяет хеши и пересобирает
строго разрешённый candidate. Аудит сравнивает все остальные host objects,
конфигурации профилей и привязки нод. Существующие staging-команды для установки
прямых транспортов для этого переноса не используются.
