# Антиглушилка: базовые 300 ГБ

Подготовлено локально 12 октября 2026. Рабочая база и Remnawave этим изменением не обновлялись.

## Что меняется

- База тарифов с антиглушилкой: 200 → 300 ГБ на период; цены и пакеты докупки без изменений.
- Обычные подписки остаются без лимита трафика.
- Существующая добавочная миграция увеличивает базу и общий лимит на разницу. Докупленный и перенесённый трафик не обнуляется: 200 + 50 ГБ → 300 + 50 ГБ.
- Счётчик использованного трафика, срок подписки и дата следующего сброса не меняются. Синхронизация Remnawave использует `NO_RESET`, без сброса потребления.
- Повторный запуск миграции не добавляет ещё 100 ГБ. Более высокую базу не уменьшает.

## Перед будущей установкой

1. Отдельно согласовать установку; сохранить полную резервную копию и проверить её восстановление.
2. Остановить **все** экземпляры бота/воркеров, включая автопроверки оплат и сбросы трафика, до запуска миграции. Не запускать старый и новый код одновременно.
3. На копии базы сверить `base_traffic_bytes`, `carried_traffic_bytes`, `current_paid_traffic_bytes`, `current_period_limit_bytes`, `last_known_used_traffic_bytes`, `traffic_reset_at` и срок подписки до/после изменения.
4. Запустить новый код: миграция выполняется до воркеров; затем фоновая синхронизация передаёт активным подпискам увеличенный лимит. Проверить результат в Remnawave, включая подписки, исчерпавшие старый лимит.

Правила истечения подписок, продления и ежемесячного переноса трафика этим повышением не меняются. Существующие конкурентные операции сброса/докупки нельзя запускать параллельно с миграцией. Старые рекламные видео с надписью «200 ГБ» не перерисованы; их нельзя использовать как описание обновлённого тарифа.

## Проверки

343 теста: 342 прошли, один необязательный браузерный preview пропущен. Включены семь независимых проверок повышения базы, в том числе фактического SQL миграции в одноразовой PostgreSQL/WASM-базе: докупки/перенос, исчерпанный лимит, сохранённые поля истёкшей подписки, повторный запуск и отсутствие сброса потребления. Рабочие пользовательские данные не использовались.
